# The BLE contract

Everything an app needs to talk to the display, written so it can be built without asking.
Contract revision **1.0.0** (tag `protocol-v1.0.0`), protocol version **1**.

| File | What it is | How it is kept honest |
|---|---|---|
| [`../ble-protocol.md`](../ble-protocol.md) | the specification: characteristics, CBOR keys, security level, delivery rules, connect sequence | reviewed by hand; every number is pinned by the vectors below |
| [`vectors/*.json`](vectors/) | **golden vectors** — hex payloads plus what the firmware's real codec decodes from them; `categories.json` (hazard ids, German labels, voice clips); `constants.json` | generated by `test/gen_vectors.cpp`; the CTest case `contract_vectors` fails if they drift from the codec |
| [`vectors/sign-rules.json`](vectors/sign-rules.json) | step-by-step sign-list scenarios + the full conflict table | generated by `tools/gen_sign_vectors.py`; CI fails on a diff |
| [`sign-rules.json`](sign-rules.json) | the 58 vendored signs (VzNr, wire code, official German name, column) and the replacement rules the **app** applies | source of truth; Python reference `tools/sign_rules.py`; Dart data is generated from it |
| [`responsibilities.md`](responsibilities.md) | who decides what (app vs display) and what the app does when a capability bit is missing | — |
| [`uuid-proposal.md`](uuid-proposal.md) | the UUID base decision (frozen) | decided |
| [`melden-lock-proposal.md`](melden-lock-proposal.md) | withdrawn proposal: app-controlled report lock | withdrawn |
| [`manifest.schema.json`](manifest.schema.json), [`manifest.example.json`](manifest.example.json) | the update manifest ([`../release-format.md`](../release-format.md)) | schema-validated example in CI |
| [`../../protocol/dart/`](../../protocol/dart/) | pure-Dart package `tn_display_protocol` (no Flutter, no Bluetooth) | its tests run every vector in CI |

## Regenerating

```bash
cmake --build build --target bdsp_gen_vectors
build/test/bdsp_gen_vectors docs/contract/vectors      # codec-derived vectors
python tools/gen_sign_vectors.py                         # sign-rule vectors
python tools/gen_dart_sign_rules.py                      # embeds sign-rules.json in the Dart package
```

## How to read a vector

Each file in `vectors/` has `vectors: [{name, kind, canonical, note, hex, decodeOk, decoded}]`:

- `kind: "encoded"` — the firmware's encoder produced `hex` from a model value;
  `kind: "input"` — `hex` was written by hand (an older app, unknown keys, truncation) and `decoded`
  is whatever the firmware's *decoder* returned.
- `decodeOk: false` — the payload must be **rejected** (`decoded` is `null`).
- `canonical: true` — an app encoder for that message should emit exactly these bytes (the Dart
  package does). Device → app messages (`event.json`, `device-info.json`) are decode-only for apps.
